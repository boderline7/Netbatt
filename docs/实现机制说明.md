# NetBatt v4 实现机制说明

> **注意：本文描述的是 v4，热点部分已在 v5 被推翻重写。**
> 现行热点实现见 [热点决策表.md](热点决策表.md)；
> 本文的充电章节（§5）仍然有效，§3/§4/§6 已被 v5 取代。

这份文档只讲「代码到底怎么跑的」，不重复需求背景。涉及四个子系统：
进程模型、车用（断电）判定、热点状态机、充电控制，以及它们之间的交叉点。

版本：v4.0.0 / versionCode 400

## 1. 进程模型

```
Magisk
 ├── post-fs-data.sh          early mount 之后、zygote 之前
 │     └── 补属主/权限（priv-app、permissions xml、bin/*.sh、api.sh）
 │
 └── service.sh               boot_completed 之后
       ├── 按 versionCode 变化清 WebView 缓存（app_webview / cache）
       ├── sleep 8            等 USB / power_supply 节点枚举完，否则开机瞬间判成断电
       ├── pkill 旧守护       loop.sh / netbatt.sh / nb-daemon.sh
       ├── setsid nb-daemon.sh adb-restore    后台等 adbd 起来再恢复无线 ADB
       └── setsid nb-daemon.sh               主守护
```

主守护 [nb-daemon.sh](../netbatt/bin/nb-daemon.sh) 是一个**单进程死循环**，
不是旧版那种「每 5 秒 fork 四个 sh」：

```
写 pid → log_boot → chg_init → start_web
loop:
    nb_cfg_reload        重新读 config.sh，网页改完立刻生效
    power_tick           状态机推进（热点）
    chg_once             充电采样 + 阈值控制
    ensure_web           httpd 挂了就拉起来
    sleep max(POLL_INT, 5)
```

单实例靠 `/data/adb/netbatt/daemon.pid`：启动时先 kill 掉里面记的旧 pid。
代价是 `power_tick` 里 `hs()` 会阻塞最多 4 秒（等接口起来），这时 web 请求仍由
独立的 httpd 进程处理，不受影响。

网页：busybox `httpd -f -p 8080 -h webroot`，CGI 固定映射 `webroot/cgi-bin/`。
`ensure_web` 每轮 `pgrep -f "httpd -f -p 8080"` 检查。

## 3. 车用（断电）判定

### 3.1 三个信号

```sh
sig_power()    # 充电器存在/在线
  对 usb、ac、dc、wireless 四个 power_supply 节点：
    present == 1  → 命中（只看“插着没有”，不受停充影响）
    online  == 1  → 命中（看在不在供电）

sig_charge()   # 电池在进电
  status ∈ {Charging, Full} → 命中
  或 current_now > 0        → 命中
```

四个节点里任何一个存在即可，没有的自动跳过（不同机型节点不一样）。

### 3.2 合成

```sh
car_sig() =
    供电                       # sig_power 命中时
  + 充电                       # 仅当 !chg_suspended 时才采信 sig_charge
```

输出为空字符串 = 判定「没在用车」。

### 3.3 为什么停充期间不采信电池信号

这是本设计里最容易踩的坑，单独说明。

充电阈值到顶后，模块会主动停充。停充的**副作用**是：

- `battery/status` 从 `Charging` 变成 `Not charging` / `Discharging`
- `battery/current_now` 从正数变成 0 或负数

如果 `sig_charge` 照常参与，就会变成：

```
充满 88% → chg_once 下发 off → status=Discharging
         → sig_charge 假 → car_sig 变空
         → 状态机认为“车断电了” → 120 秒后关热点
```

**模块用自己的手关掉了自己的另一个功能。** 所以：

```sh
chg_suspended() = [ -f chg.on ] && [ "$(cat chg.state)" = "off" ]
```

停充期间 `car_sig` 完全不看电池，只认 `present` / `online`。

### 3.4 残留风险

极少数机型在 `input_suspend=1` 时会把 `usb/online` 一起置 0。这时 `present` 通常是 1，
能兜住；如果 `present` 也不存在，就会复现上面的误判，日志特征：

```
充电控制: on -> off（88% 32℃ 上限 88 恢复 83）
车用信号: 无
热点: 关闭（断电，持续 120s）
```

处理办法：把 `CHG_MODE` 改成 `soc`（写目标电量，不切断输入路径），不用改代码。

### 3.5 判定频率与代价

`power_tick` 每 `POLL_INT`（默认 10 秒）读一轮，每次 4~8 次 `cat`，可忽略。
信号变化会经 `log_chg` 去重后写一行日志：

```
车用信号: 供电 充电
车用信号: 无
```

## 4. 热点状态机

入口 `power_tick()`，纯函数式：读状态 → 算 want → 比较 real → 执行。

### 4.1 输入

| 变量 | 来源 |
|---|---|
| `AUTO_HS` | 随车自动化总开关，1/0 |
| `HOTSPOT_MODE` | `auto` / `always_on` |
| `PAUSE_UNTIL` | 暂停到期时间戳，0 = 未暂停 |
| `pw.hold` | 保持关闭标记 |
| `sig` | `car_sig()` 的结果 |
| `real` | `ap_running()` → 1 / 0 |

### 4.2 决策顺序

```
1. sig 为空      → 删 pw.hold（新的上电沿，允许重新开启）
2. AUTO_HS ≠ 1   → 清所有计时器，直接返回（完全不碰热点）
3. PAUSE_UNTIL > now → want=0，why=暂停，auto_mode=0
4. 否则按模式：
     always_on → want=1，why=常开，auto_mode=0
     auto      → sig 非空 ? want=1,why=车用 : want=0,why=断电，auto_mode=1
5. want=1 且 pw.hold 存在 → want=0，why=保持关闭
6. 回滞：auto_mode=1 用 ON_CONFIRM/OFF_CONFIRM，否则 0（立即执行）
7. want=1 & real=0 → 计时 pw.on_since，到点开
8. want=0 & real=1 → 计时 pw.off_since，到点关
9. 两边都相等      → 清计时器，进空转检查（§4.5）
```

注意顺序：**第 1 步删除 hold 在第 2 步之前**，所以即使关掉了自动化，
断电也会清掉 hold，不会把「下次通电应该重开」的语义丢掉。

### 4.3 回滞与时序

| 场景 | 延迟 | 结果 |
|---|---|---|
| 点火 → 有电 | 5 秒（`ON_CONFIRM`） | 开热点 |
| 熄火 → 断电 | 120 秒（`OFF_CONFIRM`） | 关热点 |
| 切到 `always_on` | 0 | 立即开 |
| 切到 `auto` | 0 | 立即按信号决定 |
| 暂停 | 0 | 立即关 |
| 空转超时 | 0 | 立即关 |

另外有一个 **30 秒开热点冷却**（`pw.try`）：系统偶尔会自己把热点收掉（比如被省电策略杀），
状态机会在下一轮重新拉起，但两次尝试至少隔 30 秒，避免每 10 秒重建一次把
TetheringManager 打崩。

### 4.4 pw.hold：保持关闭

一个文件，两种来源，一个语义：**本次通电期间不要再自动开**。

| 触发 | 位置 |
|---|---|
| 空转 15 分钟无客户端 | `power_tick` |
| 用户点「立即关热点」 | `set_hs 0` |

清除时机：

- 电源断开（`sig` 为空）
- 用户点「立即开热点」
- 切模式（`set_mode`）
- 重新打开自动化（`set_auto_hs`）

没有这个标记会出现死循环：手动关 → 0.1 秒后状态机发现 want=1&real=0 → 又开。

### 4.5 空转保护

只在 `auto` 模式生效（`always_on` 是用户明确要求不关）。

```
条件：auto_mode=1 && real=1 && IDLE_OFF_MIN>0

ap_clients > 0  → 删 idle.since，返回
ap_clients == 0 → idle.since 为空则记录当前时间；
                  距 idle.since ≥ IDLE_OFF_MIN*60 → pw.hold + 关热点
```

`ap_clients()` 的判定：

```sh
a=$(ap_iface)
n=$(iw dev "$a" station dump | grep -c '^Station')
if n == 0:  n=$(ip neigh show dev "$a" | grep -cE 'REACHABLE|STALE|DELAY')
```

`iw` 是首选，因为它数的是「关联上的 station」；`ip neigh` 只能看到有 IP 交互过的，
设备连上但没请求 DHCP 时会漏。`iw` 不存在或被 SELinux 拦了才退回后者。

### 4.6 热点的真实开关

```sh
hs() {
  am broadcast -n com.netbatt.console/.TetherReceiver --ei type 0 --ez on true/false
  # 开：wait_for 4 ap_is_up
  # 关：wait_for 4 ap_down
}
```

- 实际执行者是模块自带的特权应用 `NetBattConsole`（`TETHER_PRIVILEGED`），
  它调 `TetheringManager.startTethering/stopTethering`。
- **`--ez` 必须用 `true`/`false`**。AOSP 的 `am` 用 `Boolean.parseBoolean` 解析，
  传 `1` 会被当成 `false` —— 旧版 `--ez on 1` 在浏览器里其实一直没生效。
- 等待 4 秒只是为了让状态尽快反映真实值，失败不重试，下一轮状态机会补。

### 4.7 热点是否在跑的判定

```sh
ap_iface()      依次试 wlan2 ap0 swlan0 softap0 wlan1，
                再兜底 `iw dev` 里 type AP 的第一个接口
ap_is_up()      该接口有非 127.0.0.1 的 IPv4 地址
ap_running()    ap_is_up ? 1 : 0
```

**只看接口存在是不够的**：热点关掉后 `ap0` 会残留成 `state DOWN` 且没有地址，
旧版因此出现过「状态机以为热点还开着，于是去关它」的误判。

## 5. 充电控制

### 5.1 两条通道，语义完全不同

| 平台 | 通道 | 默认节点 | 写入语义 |
|---|---|---|---|
| 高通 | `switch` | `/sys/class/qcom-battery/input_suspend` | `0` = 允许充电，`1` = 暂停 |
| 联发科/天玑 | `soc` | `/sys/class/power_supply/battery/keep_chg_soc` | 写**目标电量**，充到即停 |

`soc` 通道下发停充 = 写 `CHG_SOC_OFF`（默认 5，低于当前电量即停止）；
恢复 = 写 `CHG_SOC_ON`（默认 100）。

**这两套不能混用**：往骁龙节点写 5/100 没有意义，往天玑节点写 0/1
等于把目标电量设成 0%/1%，会一直不充电。

### 5.2 通道怎么选

```
1. 缓存 chg.node 命中且节点仍存在 → 直接用
2. CHG_MODE 强制指定 → 但要求节点存在，不存在则继续往下
3. 按平台定优先级：
     mtk  → 先试 soc 节点
     其它 → 先试 switch 节点（CHG_ON=0 / CHG_OFF=1）
4. 通用探测列表：
     qcom-battery/input_suspend        0:1
     battery/input_suspend             0:1
     charger/charging_enabled          1:0
     battery/charging_enabled          1:0
     battery/batt_slate_mode           0:1
     SOC_PATH                          （soc 通道）
5. 都失败 → CHG_CH=none，UI 显示「通道 -」
```

平台判定：`getprop ro.board.platform`

- `mt*` / `mtk*` → mtk
- `msm*` `sdm*` `sm[0-9]*` `kona` `lahaina` `waipio` `taro` `blair` `sun` `cape` → qcom
- 其它 → other（按高通处理）

`chg_writable()` 的做法：先看 `stat -c %A` 有没有 `w`；拿不到权限位才退化成
「写回原值」探测。**这个写回是唯一可能被状态查询触发的硬件写入**，靠缓存规避——
网页 5 秒刷新只读缓存，不会重新探测。

### 5.3 阈值逻辑

每 `POLL_INT` 秒跑一次 `chg_once`：

```
cap ≤ 15              → on     （低电量，无论温度都先充）
temp ≥ MAX_TEMP(45)   → off    （过温，优先于上限）
cap ≥ PAUSE_CAP(88)   → off
cap ≤ RESUME_CAP(83)  → on
其它（84~87）          → 保持上次状态
```

中间 84~87 那段是回滞区，不会来回切。

### 5.4 写入时机

```sh
if 状态变化 || 从未写过 || 距上次写 ≥ 600 秒:
    chg_apply
```

十分钟兜底是因为部分 ROM 在插拔、息屏、充电器协商后会把节点重置回默认值；
只在变化时写会「悄悄失效」，用户以为还在控制其实已经放开了。

### 5.5 还原

- 用户点「充电控制 关」→ `chg_ctl stop`：写 `chg.off`、删 `chg.on`、`chg_apply restore`
- `soc` 通道的 `restore` 写的是接管前备份的 `soc.orig`，不是硬编码 100，
  不会顶掉系统自带的充电保护
- 充电控制在关闭状态下，`chg_once` 每轮只做 `restore`（值相同则跳过写）

## 6. 三个子系统的交叉点

这是本次复核重点，列出全部耦合关系。

### 6.1 停充 → 车用判定

**耦合**：停充会改 `status` 和 `current_now`。
**处理**：`chg_suspended` 时 `car_sig` 不采信电池信号，只认 `present`/`online`。
**剩余风险**：见 §3.4。

### 6.2 断电 → 充电控制

**无耦合**。车断电后手机会关机，`chg_on` 的节点状态停留在最后一次写入。
重启后 `chg_once` 会按当前电量重新决策，通常第一轮就会恢复充电。
只有在「关机前刚好停充 + 开机后电量仍在 84~87 回滞区」时，
会保持 `off` 到电量掉出该区间，这是预期行为。

### 6.3 充电控制 → 热点开关

**无直接耦合**，只有 §6.1 这一条间接通路（充电状态属于车用信号的一部分）。
热点开关不依赖电池百分比，`PAUSE_CAP` 只影响充电，不会直接触发热点开关。

### 6.4 pw.hold 与暂停

两个都能让热点「该开却不开」，但来源不同：

| | 触发 | 解除 |
|---|---|---|
| `PAUSE_UNTIL` | 用户点暂停 | 到点 / 用户恢复 / 切模式 |
| `pw.hold` | 空转关 / 手动关 | 断电 / 手动开 / 切模式 / 重开自动化 |

暂停优先于模式判断；`pw.hold` 在暂停之后、回滞之前生效。
两者同时存在时，暂停到期后仍会被 `pw.hold` 压住，直到断电。

## 7. 关于 USB

v4 已把 USB 网络共享**整段移除**：自动共享、保留 ADB、拔插触发、USB 状态展示、
网段 / 端口转发 / DHCP 接管，一行不留。

现在代码里唯一剩下的 "usb" 是 `/sys/class/power_supply/usb` —— 一个供电节点，
只用于 `sig_power`。它判断的是「充电器插着没有」，和网络共享无关。

移除原因（两条独立的墙，任一条都足以否掉）：

1. **方向反了**。车机那个 USB 口是 device 模式
   （`persist.sys.usb.config=carplay_carlife,adb`），手机插上去手机变 host，
   手机没法把网络「推」给车机。
2. **车机框架不认新网卡**。DesaySV 车机的 `EthernetTracker` 白名单硬编码
   `eth0_101|usb0`，模块建出来的 `rndis0` / `ncm0` 不会被接管，拿不到接口能力。

附带一个本机的坑：直接 `setprop sys.usb.config rndis,adb` 是空转——
属性回显成功、`/config/usb_gadget` 里也建了 function，但配置没链接、UDC 没绑定，
内核根本不建网卡。这条链接是厂商 HAL 做的，写属性不会触发。

## 8. 配置项与默认值

| 键 | 默认 | 作用域 |
|---|---|---|
| `AUTO_HS` | 1 | 热点自动化总开关 |
| `HOTSPOT_MODE` | `auto` | `auto` / `always_on` |
| `PAUSE_UNTIL` | 0 | 暂停到期时间戳 |
| `ON_CONFIRM` | 5 | 有电持续秒数 |
| `OFF_CONFIRM` | 120 | 断电持续秒数 |
| `IDLE_OFF_MIN` | 15 | 空转关闭分钟数，0 = 关闭该功能 |
| `POLL_INT` | 10 | 守护轮询秒数，最小 5 |
| `PAUSE_CAP` / `RESUME_CAP` | 88 / 83 | 充电上限 / 恢复 |
| `MAX_TEMP` | 45 | 过温停充 |
| `CHG_MODE` | `auto` | `auto` / `switch` / `soc` |
| `CHG_SWITCH` | qcom input_suspend | switch 通道节点 |
| `SOC_PATH` | battery/keep_chg_soc | soc 通道节点 |
| `CHG_SOC_OFF` / `CHG_SOC_ON` | 5 / 100 | soc 通道停/开值 |
| `ADB_TCP` / `ADB_PORT` | 0 / 5555 | 无线 ADB |
| `LOG_MAX` / `LOG_ON` / `SAMPLE_INT` | 3MB / 1 / 15 | 日志 |

v3 升级到 v4 时，只迁移上表里的充电、ADB、日志项，其余（网段、USB 类型、
固定入口、DHCP 接管等）直接丢弃。

## 9. 已知边界

1. **点烟器常电** → 断电信号永远不来，自动关不触发。需要改接 ACC 降压线。
2. **`ON_CONFIRM=5` 秒** → 点火到热点可用约 5~15 秒（含系统 tethering 启动时间）。
3. **空转 15 分钟** → 车里没人但热点开着，15 分钟后会关；有人上车需重新通电或手动开。
4. **`ap_clients` 依赖 `iw`** → 被 SELinux 拦时退回 ARP 表，设备刚连上未取 IP 的那几秒会算 0。
5. **充电通道探测失败** → UI 显示「通道 -」，充电控制按钮仍可点但实际不生效，日志无写入记录。
6. **守护进程重启** → `pw.on_since` / `idle.since` 保留，回滞不会因重启清零。

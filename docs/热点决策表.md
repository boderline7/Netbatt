# 热点决策表（定版）

> 只描述热点子系统。充电模块不在此表内，只向采集层提供事实。
> 本文是重写的依据，代码按「采集 → 决策 → 执行」三段实现。

## 1. 三层边界

| 层 | 输入 | 输出 | 禁止 |
|---|---|---|---|
| 采集器 | sysfs / Android | `POWER` `CHARGING` `CHG_HELD` `AP_REAL` `CLIENTS` | 不决策，不写硬件 |
| 决策器 | 配置 + 用户操作 + 采集事实 | `TARGET_HS` | 不读硬件，不写硬件 |
| 执行器 | `TARGET_HS` + `AP_REAL` | 开关动作、重试、失败日志 | 不改配置，不碰充电 |

## 2. 采集层输出

| 事实 | 来源 | 说明 |
|---|---|---|
| `POWER` | `power_supply/{usb,ac,dc,wireless}` 的 `present==1` 或 `online==1` | **已确认值**，见 §3 |
| `CHARGING` | `battery/status ∈ {Charging,Full}` 或 `current_now>0` | 原始值 |
| `CHG_HELD` | `chg.on` 存在 且 `chg.state == off` | 软件主动停充 |
| `AP_REAL` | 接口存在且有非 127 的 IPv4 | 热点实际状态 |
| `CLIENTS` | `iw dev <ap> station dump` 数 Station，退回 `ip neigh` | 已连设备数 |

辅助合成（仅当 `present`/`online` 都不存在时兜底）：

```
POWER_RAW = POWER(节点) || (!CHG_HELD && CHARGING)
```

`CHG_HELD` 只用来**排除**「软件自己停充导致的假断电」，不参与任何热点决策。

## 3. POWER 的确认（回滞）

原始的 `POWER_RAW` 不能直接参与决策——点火瞬间电压跌落会让它闪一下 0。

```
RAW=1 持续 ≥ 5 秒      → POWER=1
RAW=0 持续 ≥ 120 秒    → POWER=0
其它情况               → POWER 保持原值
```

状态存一行：`power.state` = `RAW SINCE POWER`。
文件不存在时（首次启动 / 升级）直接取当前 RAW 初始化，`service.sh` 的 8 秒等待保证此时节点已就绪。

**下游只看 `POWER`，不看 `RAW`。** SUPPRESS 的解除也只看 `POWER` 由 1 变 0。

## 4. 决策主表

| `MODE` | `POWER` | `SUPPRESS` | `TARGET_HS` | 说明 |
|---|---|---|---|---|
| `ON` | 1 | 忽略 | **1** | 有电就开 |
| `ON` | 0 | 忽略 | **0** | 断电就关，重新通电再开 |
| `OFF` | 任意 | 忽略 | **0** | 用户明确要关 |
| `AUTO` | 1 | 0 | **1** | 车在用 |
| `AUTO` | 1 | 1 | **0** | 本供电周期被抑制 |
| `AUTO` | 0 | 任意 | **0** | 车没在用 |

`ON` 与 `AUTO` 的唯一差别：**`ON` 不参与空转保护、忽略 `SUPPRESS`**。
`ON` 不是「无条件常开」——断电仍然关闭。

## 5. 用户操作

| 当前 MODE | 操作 | POWER | 结果 |
|---|---|---|---|
| 任意 | 选 `ON` | — | `MODE=ON`，清 `SUPPRESS` |
| 任意 | 选 `OFF` | — | `MODE=OFF` |
| 任意 | 选 `AUTO` | — | `MODE=AUTO`，清 `SUPPRESS` |
| `AUTO` | 点「开热点」 | 1 | 清 `SUPPRESS`，立即开 |
| `AUTO` | 点「开热点」 | 0 | **一次性立即开**，不改 MODE、不落任何标记；下一轮 AUTO 规则判定 `TARGET=0` 后自动关 |
| `AUTO` | 点「关热点」 | 1 | 置 `SUPPRESS`，立即关 |
| `ON` / `OFF` | — | — | 不提供手动开关按钮 |

暂停已砍掉：需要「暂时别开」就切 `OFF`，需要「一直开」就切 `ON`。

## 6. SUPPRESS

唯一语义：**本次供电周期内，`AUTO` 不再自动开启**。

| 事件 | SUPPRESS |
|---|---|
| 空转：`AP_REAL=1` 且 `CLIENTS=0` 持续 15 分钟 | 置 1 |
| `AUTO` 下点「关热点」 | 置 1 |
| `POWER` 由 1 变 0 | 清 0 |
| 切到 `ON` / `OFF` / `AUTO` | 清 0 |
| `AUTO` 下点「开热点」 | 清 0 |

## 7. 空转保护

```
条件：MODE=AUTO && AP_REAL=1 && CLIENTS=0 && 持续 ≥ IDLE_OFF_MIN(15) 分钟
动作：SUPPRESS=1
```

`ON` 模式不做空转保护。人回来后手动点「开热点」即可恢复（清 `SUPPRESS`），
或断电再通电。

## 8. 执行器

| `TARGET_HS` | `AP_REAL` | 动作 |
|---|---|---|
| 1 | 0 | 发开启命令；距上次尝试 < 30 秒则跳过 |
| 0 | 1 | 发关闭命令 |
| 1 | 1 | 不动 |
| 0 | 0 | 不动 |

- 执行后**重新读** `AP_REAL`，不假设成功。
- 失败只写日志，不搞失败计数状态机，下一轮自然重试。
- `AP_LAST_TRY` 归执行器，不参与决策。

## 9. 变量清算

| 旧 | 新 | 处置 |
|---|---|---|
| `AUTO_HS` | — | 删除 |
| `HOTSPOT_MODE` | `MODE` | 三值 `AUTO/ON/OFF` |
| `PAUSE_UNTIL` | — | 删除（暂停砍掉） |
| `pw.hold` | `SUPPRESS` | 语义单一化，仅 `AUTO` 生效 |
| `pw.on_since` / `pw.off_since` | `power.state` | 合并为一行：`RAW SINCE POWER` |
| `pw.try` | `AP_LAST_TRY` | 移入执行器 |
| `idle.since` | `idle.since` | 保留，采集层计时 |

决策层从 8 个变量降到 **2 个持久化（`MODE`、`SUPPRESS`）+ 1 个事实（`POWER`）**，三者互不改写。

## 10. 与 v4 的差异

| 项 | v4 | 新 |
|---|---|---|
| 总开关 | `AUTO_HS` 另设 | 由 `MODE` 覆盖 |
| 暂停 | 独立时间戳 | 删除 |
| 空转后的锁 | `pw.hold`，两种来源混用 | `SUPPRESS`，语义单一 |
| 断电清锁 | 用原始信号清，抖动会误清 | 用确认后的 `POWER` 清 |
| 常开模式 | 无条件开，断电也开 | 有电开、断电关 |
| AUTO 下手动开（断电） | 无定义 | 一次性立即开，下轮自动关 |

## 11. 待确认

1. `ON` 模式断电即关——已按此定版。若希望「车上断电后靠电池继续开」，需要另开一个模式。
2. `AUTO` 断电时点「开热点」只亮 10 秒左右（下一轮就关）。确认这是可接受的行为。
3. 空转 15 分钟期间若一直没人连，热点会关；此时手机仍在电池供电，页面仍可访问。
